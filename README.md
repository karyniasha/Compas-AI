# Компас — MVP 0.2.1 (демонстрационный режим без API)

Адаптивный наставник для исследования жизненных развилок. Три сценария: Георгий (история: СПбГУ, СГУ, РГГУ, МГУ), стажировка, адаптация на первой работе. Интерфейс работает как **контролируемый локальный сценарий**. K-034 добавляет отдельный опциональный адаптер LLM; подключение свободного диалога и согласия к интерфейсу запланировано в K-033. Факты о вузах берутся из локального JSON-реестра с официальными ссылками и датой последней редакционной проверки.

## Установка и запуск

Нужен Python 3.10+ (целевой 3.11+). API-ключ **не нужен**.

**Windows PowerShell:**
```powershell
cd kompas_mvp
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

**macOS / Linux:**
```bash
cd kompas_mvp
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

После запуска открыть `http://localhost:8501`. При невозможности установить зависимости проверить подключение к Интернету. Само приложение не обращается к внешнему LLM/API и не требует живого доступа к сайтам вузов.

## Настройка LLM (K-034, отдельно от интерфейса)

**Без ключа приложение продолжает полностью работать локально.** Пакет `openai` необязателен для запуска Streamlit и тестов. Даже с ключом интерфейс использует `RuleBasedModel` и не отправляет пользовательские ответы наружу. Само создание `OpenAIResponsesModel` также не вызывает API.

Для явного вызова адаптера из Python установите официальный SDK и задайте окружение в текущем сеансе PowerShell из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-llm.txt
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new("", (Read-Host "OpenAI API key" -AsSecureString)).Password
$env:OPENAI_MODEL = Read-Host "ID доступной в вашем проекте модели с Responses API и Structured Outputs"
```

Ключ вводится скрыто и не записывается в команду или историю команд. Не вставляйте его в исходники, логи, Git или чат. На macOS/Linux задайте те же переменные через менеджер секретов либо скрытый ввод терминала. `.env` автоматически не загружается. Модель выбирается явно через `OPENAI_MODEL`, значения по умолчанию нет; доступность модели зависит от проекта OpenAI.

Необязательная ручная проверка делает **реальный запрос** с техническим контекстом без пользовательских ответов:

```powershell
.\.venv\Scripts\python.exe -c "from kompas.llm_adapter import OpenAIResponsesModel; result = OpenAIResponsesModel().generate_followup({'topic': 'programs'}, ()); print(result.mode); print(result.text)"
```

После проверки можно очистить переменные текущего сеанса:

```powershell
Remove-Item Env:OPENAI_API_KEY, Env:OPENAI_MODEL -ErrorAction SilentlyContinue
```

Контракт остаётся `LanguageModel`: `generate_followup(context, allowed_facts)` возвращает `FollowupResponse` с фактическим `mode="llm"` либо `mode="rules"`. `llm` означает, что модель выбрала локальный шаблон; окончательный текст составляет Python. Текст также явно сообщает режим. В `context["year"]` передаётся выбранный год, в `allowed_facts` — кортеж `Fact`. Адаптер отбрасывает неподтверждённые, просроченные и не соответствующие году факты; передаёт URL, даты и оговорки допущенных записей. Неизвестное остаётся `null`.

Используется [OpenAI Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): `responses.create`, JSON-схема, `store=False`, таймаут 15 секунд, без повторных попыток. При отсутствии ключа, модели или SDK, сетевой ошибке, таймауте, отказе, пустом/некорректном ответе либо постороннем ID источника возвращается вопрос `RuleBasedModel`. Тексты исключений API не выводятся и не логируются адаптером.

После исправления P1/P2 LLM возвращает **только** `template_id` и `fact_id`. Допустимые шаблоны: `programs`, `admission`, `costs`, `missing_information` (для них `fact_id=null`) и `review_fact` (обязателен ID допущенного источника). Например: `{"template_id": "admission", "fact_id": null}`. Произвольный текст, дополнительные поля, неизвестные шаблоны, недопустимые ID и URL в любом регистре отклоняются с локальным возвратом.

Python берёт вопрос из локального списка. Для `review_fact` добавляет исходное утверждение только из разрешённой записи, её URL, год набора, дату проверки, срок актуальности и примечание. Текст LLM и пользовательские утверждения в итоговый вопрос не подставляются. Даже правильный `fact_id` не разрешает модели добавлять собственный текст. Качество исходной базы зависит от редакционной проверки; уместность выбора шаблона реальной моделью ещё не проверена. `evaluate_free_answer` возвращает локальный `FreeAnswerFeedback(assessed=False, ...)` и ничего не отправляет в API; экзаменатор и рубрики не изменены.

Перед передачей реальных ответов вызывающий код обязан получить согласие пользователя. Подключение диалога к Streamlit и реализация согласия — отдельная K-033; K-034 её не реализует.

## Тесты

```bash
python -m unittest discover -s tests -v
python -m compileall -q .
```

В среде сборки MVP 0.2.1 проверки прошли: 27/27 тестов на Python 3.13.5. **Владелец подтвердил браузерный запуск MVP 0.2 на Windows 26.10.2026; новая версия 0.2.1 на его компьютере ещё не проверена.** В среде сборки Streamlit не установлен, поэтому запуск UI проверен заглушкой (`tests/test_app_smoke.py`); она не заменяет ручную проверку в браузере. Новый чек-лист — `docs/ACCEPTANCE_0_2_1.md`.

K-034 после исправления P1/P2, 27.10.2026: **55/55 тестов на Python 3.11.9**. API-клиент подменяется; проверены успех, отказы и возврат к правилам, фильтрация фактов, проверка результата и отсутствие сетевых вызовов из UI при настроенном ключе. Добавлены проверки выдуманных утверждений без источника и с разрешённым ID, выбора шаблона, подстановки только исходной записи и URL в разном регистре. Тесты прошли без установленного SDK `openai`; в тестах адаптера сетевые подключения запрещены заглушкой и проверяется отсутствие попыток подключения. Реальный запрос к OpenAI и браузерная приёмка этой итерации не проводились.

## Сценарий проверки 0.2

1. Выбрать «Георгий: выбор вуза», указать 2027, бюджет «Пока не знаю» и завершить шесть этапов.
2. Во вкладке «Источники» переключить «Программы», «Условия поступления», «Расходы и проживание»: просмотреть ссылки, архив 2026 и неизвестные значения.
3. Решить кейсы «Тренажёра», специально выбрать неправильный вариант и убедиться, что показана причина ошибки, её категория и рекомендация повтора; скачать Markdown-отчёт с датами источников.
4. Выбрать два других сценария и проверить их маршруты и кейсы.

## Что реально работает

- Детерминированные этапы для трёх сценариев и 11 кейсов; проверка порядка прохождения и ответов. Для каждого неверного варианта добавлены отдельная причина ошибки, объяснимый принцип и категория; на основе последних ответов рекомендуются повторы.
- Локальный информационный режим по четырём вузам: статусы источников, год приёма, даты, неизвестные данные, предупреждения о 2027.
- `LanguageModel`, локальный `RuleBasedModel` и отдельный `OpenAIResponsesModel` с автоматическим локальным возвратом. **В интерфейсе нет вызовов внешнего LLM.**
- Память **последнего ответа и выбранного варианта на каждый кейс в текущей сессии**; отчёт Markdown показывает категории ошибок и повтор. Это не постоянная и не межсессионная адаптация.

## Что ещё не работает

Нет базы подтверждённых финансовых данных, правил поступления 2027, информации по вторичным сценариям, памяти между запусками, истории всех попыток, адаптивного повтора, PDF, свободной семантической оценки ответов, LLM-диалога в интерфейсе и автоматического обновления сайтов. Не рассчитывается вероятность поступления. Программа **не выбирает вуз** за пользователя.

## Структура и документация

- `app.py` — Streamlit UI.
- `kompas/core.py` — сценарии, тесты решений, Markdown.
- `kompas/knowledge.py` + `kompas/data/facts.json` — реестр и контролируемая выдача фактов.
- `kompas/model.py` — контракт LLM и локальный адаптер.
- `kompas/llm_adapter.py`, `requirements-llm.txt` — опциональный Responses API и его SDK.
- `kompas/examiner.py` — рубрики, объяснения всех неверных вариантов, категории ошибок и повторения.
- `tests/` — 55 unit- и headless smoke-проверок.
- `docs/PROJECT_BRIEF.md`, `REQUIREMENTS.md`, `TECH_SPEC.md`, `TASKS.md`, `DECISIONS.md`, `HANDOFF.md` — исходное ТЗ и решения.
- `docs/AUDIT_0_1.md`, `SOURCES.md`, `CHANGELOG.md`, `ACCEPTANCE_0_2.md`, `EXAMINER_0_2_1.md`, `ACCEPTANCE_0_2_1.md` — аудит, проверенные источники, изменения, рубрики и ручная приёмка.

**Секреты:** не сохранять ключи API в исходниках, репозитории или сообщениях; использовать переменные окружения/секретное хранилище. Личные ответы в интерфейсе живут только в `st.session_state` до закрытия сессии.
