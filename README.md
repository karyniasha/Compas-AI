# Компас — MVP 0.2.1 (демонстрационный режим без API)

Адаптивный наставник для исследования жизненных развилок. Три сценария: Георгий (история: СПбГУ, СГУ, РГГУ, МГУ), стажировка, адаптация на первой работе. Работающий **контролируемый сценарий**, а **не** генеративная LLM. Факты о вузах берутся из локального JSON-реестра с официальными ссылками и датой последней редакционной проверки.

## Установка и запуск

Нужен Python 3.10+ (целевой 3.11+). API-ключ **не нужен**.

**Windows PowerShell:**
```powershell
cd kompas_mvp
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

**macOS / Linux:**
```bash
cd kompas_mvp
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

После запуска открыть `http://localhost:8501`. При невозможности установить зависимости проверить подключение к Интернету. Само приложение не обращается к внешнему LLM/API и не требует живого доступа к сайтам вузов.

```bash
python -m unittest discover -s tests -v

```

## Сценарий проверки 0.2

1. Выбрать «Георгий: выбор вуза», указать 2027, бюджет «Пока не знаю» и завершить шесть этапов.
2. Во вкладке «Источники» переключить «Программы», «Условия поступления», «Расходы и проживание»: просмотреть ссылки, архив 2026 и неизвестные значения.
3. Решить кейсы «Тренажёра», специально выбрать неправильный вариант и убедиться, что показана причина ошибки, её категория и рекомендация повтора; скачать Markdown-отчёт с датами источников.
4. Выбрать два других сценария и проверить их маршруты и кейсы.

## Что реально работает

- Детерминированные этапы для трёх сценариев и 11 кейсов; проверка порядка прохождения и ответов. Для каждого неверного варианта добавлены отдельная причина ошибки, объяснимый принцип и категория; на основе последних ответов рекомендуются повторы.
- Локальный информационный режим по четырём вузам: статусы источников, год приёма, даты, неизвестные данные, предупреждения о 2027.
- `LanguageModel` как интерфейс и локальный `RuleBasedModel` для предсказуемого уточняющего вопроса. **Нет вызовов внешнего LLM.**
- Память **последнего ответа и выбранного варианта на каждый кейс в текущей сессии**; отчёт Markdown показывает категории ошибок и повтор. Это не постоянная и не межсессионная адаптация.

## Что ещё не работает

Нет базы подтверждённых финансовых данных, правил поступления 2027, информации по вторичным сценариям, памяти между запусками, истории всех попыток, адаптивного повтора, PDF, свободной семантической оценки ответов, интеграции с LLM и автоматического обновления сайтов. Не рассчитывается вероятность поступления. Программа **не выбирает вуз** за пользователя.

## Структура и документация

- `app.py` — Streamlit UI.
- `kompas/core.py` — сценарии, тесты решений, Markdown.
- `kompas/knowledge.py` + `kompas/data/facts.json` — реестр и контролируемая выдача фактов.
- `kompas/model.py` — контракт LLM и локальный адаптер.
- `kompas/examiner.py` — рубрики, объяснения всех неверных вариантов, категории ошибок и повторения.
- `tests/` — 27 unit- и headless smoke-проверок.
- `docs/PROJECT_BRIEF.md`, `REQUIREMENTS.md`, `TECH_SPEC.md`, `TASKS.md`, `DECISIONS.md`, `HANDOFF.md` — исходное ТЗ и решения.
- `docs/AUDIT_0_1.md`, `SOURCES.md`, `CHANGELOG.md`, `ACCEPTANCE_0_2.md`, `EXAMINER_0_2_1.md`, `ACCEPTANCE_0_2_1.md` — аудит, проверенные источники, изменения, рубрики и ручная приёмка.

**Секреты:** не сохранять ключи API в исходниках, репозитории или сообщениях; при появлении провайдера использовать переменные окружения/секретное хранилище. Личные ответы по умолчанию живут только в `st.session_state` до закрытия сессии.
